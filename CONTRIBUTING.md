# Contributing to NEPA MCP

Thank you for contributing to NEPA MCP. This project provides research and
screening tools for environmental and regulatory workflows. Contributions
should preserve the distinction between screening information and formal
agency, legal, consultation, jurisdictional, or permitting determinations.

Please review the [Code of Conduct](CODE_OF_CONDUCT.md),
[Security policy](SECURITY.md), [Support policy](SUPPORT.md), and
[project roles](MAINTAINERS.md) before participating.

## Development setup

NEPA MCP requires Python 3.12 or newer. The development environment uses
[`uv`](https://docs.astral.sh/uv/):

```bash
git clone https://github.com/pnnl-int/nepa-mcp-server.git
cd nepa-mcp-server
uv sync --all-groups
```

Do not commit credentials or private project data. Optional Census and EPA AQS
credentials should be supplied through environment variables or the private
per-user configuration described in the README. Repository `.env` files,
generated credential files, and client-config backups are ignored by Git.

## Repository structure

Each domain server has its own top-level directory:

```text
server_name/
├── requirements.txt
├── server.py
└── src/
    ├── apis/
    └── core/
```

The installable command, server registry, loader, client configuration, and
aggregate test proxy live in `nepa_mcp/`. Shared HTTP, ArcGIS, spatial, and
validation utilities live in `nepa_mcp_common/`.

When adding or renaming a server or tool, update every affected distribution
surface: the registry, package configuration, client examples, plugin
configuration, documentation, and tests.

## Generated files

`docs/mcp-tool-catalog.md` is generated from the live MCP contracts. Do not
edit it manually. Regenerate and verify it with:

```bash
uv run python scripts/generate_tool_catalog.py
uv run python scripts/generate_tool_catalog.py --check
```

`uv.lock` is generated by `uv`. Commit lockfile changes when project or
development dependencies change, and avoid unrelated dependency refreshes.

## Tests and quality checks

Run the following checks before opening a pull request:

```bash
uv run ruff format --check .
uv run ruff check .
uv run python -m compileall -q .
uv run pytest -q
uv run pip-audit --progress-spinner off
```

Add focused tests for behavioral changes. Tests should cover relevant MCP tool
contracts, validation and failure behavior, and partial or empty upstream
responses. Keep the default test suite reproducible without optional API
credentials.

Changes to external data integrations should preserve source URLs, retrieval
status, truncation or partial-result warnings, and other provenance needed to
review the result. Do not convert unavailable or incomplete source retrieval
into an apparently authoritative no-feature result.

## Pull requests

Keep pull requests scoped and explain:

- the user or analyst problem being addressed;
- the affected servers, tools, and external sources;
- important behavioral or schema changes;
- tests and manual validation performed; and
- known limitations or follow-up work.

Update user-facing documentation when installation, configuration, tool
contracts, data behavior, or package metadata changes. Avoid combining
unrelated formatting, generated-file, and behavioral changes when they can be
reviewed independently.

Maintainers may request changes before merging. Submitting a contribution does
not imply that it will be accepted or included in a release.

## Developer Certificate of Origin

Every commit must include a `Signed-off-by` line certifying compliance with the
[Developer Certificate of Origin 1.1](https://developercertificate.org/).
Sign off a commit with:

```bash
git commit -s -m "Describe the change"
```

The resulting commit message includes:

```text
Signed-off-by: Your Name <your.email@example.com>
```

The sign-off certifies that you have the right to submit the contribution under
the project's open-source license. It is not a copyright assignment or a
Contributor License Agreement. The name and email in the sign-off become part
of the public Git history.

If a commit is missing the sign-off, amend it before review:

```bash
git commit --amend --signoff --no-edit
```

## Reporting concerns

Use public issues only for non-sensitive bugs and usage questions. Do not place
credentials, controlled information, private project data, suspected
vulnerability details, or Code of Conduct reports in a public issue.

Code of Conduct reports should follow the private contact instructions in
`CODE_OF_CONDUCT.md`. Suspected vulnerabilities should follow the private
reporting instructions in `SECURITY.md`.
