Quick Start

Install once, then point your agent at any of the 19 servers

1

Install

Python 3.12+, pipx, and Git. One package installs all 19 servers. 

git clone https://github.com/pnnl-int/nepa-mcp-server.git
cd nepa-mcp-server
pipx install .
2

Verify

doctor exits non-zero if a server file is missing, so this is the gate before wiring up a client. 

$ nepa-mcp doctor
nepa-mcp version: 0.1.0
Python: 3.12.12
Credential file: ~/…/nepa-mcp/credentials.env (not found)
Installed servers: 19
census credentials: optional, missing CENSUS_API_KEY
epa_aqs credentials: optional, missing EPA_AQS_EMAIL, EPA_AQS_API_KEY

Actual output on a fresh install — the two credential lines are optional and only affect Census and EPA AQS. Run nepa-mcp list-servers for the full table.

3

Connect your client

The CLI merges the entries in. Unrelated MCP servers are preserved, and the existing file gets a one-time backup.

4

Ask a question

Your client launches the servers itself — nothing left to start.

  • What listed species and critical habitat are near 38.98, −76.49?
  • Build a screening map for a 20-mile project area there.
  • What does 40 CFR 1501.4 say, and when did it last change?
Instead of step 3

Codex Desktop plugin

One install for all 19 servers and the screening skill

Local marketplace

The repository ships a Codex marketplace and plugin. One install registers all 19 servers and the nepa-screening skill, which tells the agent how to establish a project area and pick the right datasets.

  • All 19 servers at once — no per-server entries
  • Bundles the screening skill and starter prompts
  • Installs from your local checkout

From the repository root, after pipx install:

codex plugin marketplace add "$(pwd)"
codex plugin add nepa-mcp@nepa-mcp-local

Start a new Codex task after installing or updating the plugin so the tools and skill are loaded. Steps 1, 2 and 4 are unchanged.
