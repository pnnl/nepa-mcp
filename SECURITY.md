# Security Policy

## Supported versions

NEPA MCP is prerelease research software. Security fixes are provided on a
best-effort basis for the latest published release or release candidate and
the current `main` branch. Older releases, prereleases, and development
snapshots may not receive security updates.

| Release line | Supported |
|---|---|
| Latest published release or release candidate | Yes |
| Current `main` branch | Yes |
| Older releases and development snapshots | No |

## Reporting a vulnerability

Do not report suspected vulnerabilities through a public GitHub issue,
discussion, or pull request.

Send an initial email to
[policyai@pnnl.gov](mailto:policyai@pnnl.gov?subject=NEPA%20MCP%20Security%20Report)
with the subject **NEPA MCP Security Report**. Identify the affected version or
commit, the affected component, a high-level description of the concern, and
your preferred contact information.

Do not include credentials, private project data, controlled information,
operational exploit code, or other sensitive material in the initial email.
The project will coordinate an appropriate private channel if additional
technical details, logs, or a proof of concept are needed.

## What to expect

Security reports are reviewed on a best-effort basis without a guaranteed
response or remediation time. The primary maintainer and designated recipients
of the PermitAI project mailbox will coordinate technical triage and any
necessary follow-up. Reporters may be asked for additional information or for
time to investigate before public disclosure.

If the concern is limited to an upstream agency service, third-party library,
or external platform rather than this repository or its packaged software,
report it to the responsible provider. If the concern involves how NEPA MCP
uses or exposes that dependency, report it through the process above.
